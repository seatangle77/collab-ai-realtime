# CoI 认知临场感编码手册

本手册依据本项目论文附录 A.6（Study 2 CoI Cognitive Presence Coding Scheme）编写。请判断每个观点单元在对话中的认知功能，而不是只看关键词或句式；不得补充原文未表达的理由、关系或结论。

## 编码前的观点单元检查

在正式编码前，先检查研究员提供的观点单元，但不得直接修改原文。

### 核心定义

- 观点单元按“一次相对独立的认知贡献”划分，不按讨论主题划分。
- 同一问题或对象可以构成一个讨论片段，但其中的提问、回答、主张、理由、补充、质疑、反驳、修正、综合和决策仍可分别构成不同观点单元。
- 内容依赖上文、回应相邻发言或共同构成完整对话，不等于属于同一观点单元。

### 不得合并的情形

出现以下任一情形时，原则上保持为多个单元：

- 说话者不同。即使后一人只是在补充、同意或回答前一人，也不得建议跨说话者合并。
- 相邻内容构成“问题—回答”“主张—反驳”“质疑—回应”或“建议—表决”关系。它们是相互关联的不同认知贡献，不是同一观点。
- 立场、主张、判断对象、核心理由、比较维度或结论发生实质变化。
- 认知功能发生变化，例如从提出问题转为给出解释，从提出可能性转为比较综合，或从分析判断转为具体排序决定。
- 后一条对前一条进行了否定、限定、修正、反例补充或新的推论。

若输入没有提供说话者信息，不得自行假定相邻内容来自同一说话者。除非文本明确显示它们是同一个未完成表达的两个部分，否则不建议合并。

### 可建议合并的情形

只有在以下条件全部满足时，才可建议合并相邻单元：

1. 明确来自同一说话者。
2. 表达同一立场、同一核心主张和同一认知功能。
3. 后一条只是对前一条未完成发言的紧接续说，或补齐同一主张不可分割的理由。
4. 合并后仍只需一个主要 CoI 编码；若两条可能需要不同编码，则不得合并。

“语义连续”“主题相同”“单独看不完整”或“合并后更像完整对话”都不是充分的合并理由。对合并存在合理疑问时，优先输出“无需调整”。

### 可建议拆分的情形

- 一个单元内包含多个可独立成立的主张、方案、理由或结论，且它们的认知功能或推理方向不同。
- 一般判断原则与运用该原则得到的具体决定具有不同认知功能，可建议拆分。
- 围绕同一判断形成、且在语义和逻辑上不可分割的“主张—理由—结论”推理链应保留为一个单元，不要仅因句子数量而机械拆分。
- “这个”“这两个”“那样”等指代依赖上文，不等于该单元没有独立认知功能，也不是拆分理由。若该发言本身完成了新的提问、判断、比较或决策，应保留为独立单元；只能依据输入中实际提供的上下文解析指代，不得补充未提供的指代对象。

### 无实质内容的片段

- 仅重复、附和、程序性话语或无实质内容的片段，不应独立形成观点单元。
- 不得为了消除“对”“有道理”等附和语，就建议将它与前一个实质观点合并。应在建议中说明该片段“不宜独立作为观点单元”。

### 程序性话语的定义与边界

- 程序性话语是仅用于管理讨论或协作过程的表达，例如安排发言顺序、邀请或催促他人继续发言、推进讨论步骤、控制时间、分配记录任务、选择记录方式、调整呈现格式或操作工具。它可能推动协作进度，但不直接提出、解释、比较、整合、修改或确认任务内容，因此不进行 CoI 编码。
- 判断是否属于程序性，应看发言操作的对象，而不是只看“先、接下来、继续、确认、没问题”等句式。若操作对象只是发言、记录、格式、时间、工具或讨论步骤，属于程序性；若操作对象是具体问题、事实、理由、比较、物品名次、解决方案或最终答案，则属于实质认知活动，应按 `TE`、`EX`、`IN` 或 `RE` 判断。单纯说“你继续说”是在催促发言，属于程序性；追问“第二名是什么”“第六名之后怎么排”等任务答案中缺失的具体内容，则不是单纯程序性，应根据其识别的实质信息缺口判断是否属于 `TE`。
- 确认流程与确认答案必须区分。“你记下来了吗？”“这样写是否清楚？”是在确认记录过程，属于程序性；“火柴15、奶粉14、手枪13，这个顺序没问题吧？”是在确认具体任务答案，属于 `RE`。
- 程序性片段与实质内容出现在同一单元时，只忽略程序性片段，不得把整个单元判为空编码。例如“接下来讨论氧气，它直接决定生存，所以应该排第一”中的“接下来讨论氧气”用于推进步骤，但后面的理由与排序方案仍须编码。

边界示例：

- “我先按照你的方式写一下，这样比较直观。”只调整记录和呈现方式，属于程序性，不编码。
- “你继续说，我来记录。”只安排发言与记录，属于程序性，不编码。
- “接下来讨论哪个物品？”只选择下一讨论步骤，属于程序性，不编码。
- “我们还没有解决指南针能否工作的问题。”指出尚未解决的实质问题，属于 `TE`，不是程序性。
- “那就确定火柴15、奶粉14、手枪13。”确认具体排序方案，属于 `RE`，不是程序性。

### 同意、附和与确认的区分

不能仅凭“对”“同意”“可以”“就这样”等词判断编码，必须判断该发言是否新增了认知内容，或是否使小组方案从讨论状态转为已确定状态。

编码前必须先检查单元中的每个分句或功能片段，再对整个单元作出判断：

1. 标出其中所有具有实质认知贡献的片段，包括事实、实质疑问、理由、比较、推论、方案和决定。
2. 将纯重复、附和、会话反馈和程序性片段视为无编码片段；它们不产生类别，但也不得抵消、覆盖或“消解”同一单元中的实质片段。
3. 只要至少存在一个实质片段，整个单元就不得返回空编码；应忽略无编码片段，并依据全部实质片段判断类别。
4. 若剩余实质片段体现一个主要认知功能，选择一个类别；若体现多个在语义和逻辑上不可分割的认知功能，允许同时选择两个或以上类别。
5. 只有当所有片段都没有实质认知贡献时，才允许返回空编码。

1. **纯附和或会话反馈：不编码。**
   - 只表示正在听、理解、赞同或鼓励对方，没有新增事实、理由、比较、归纳、方案或决定。
   - 典型表达：“对。”“嗯。”“有道理。”“我同意。”“可以。”“没错。”
   - 即使它指向前文的具体观点，只要没有新增内容，也不能因为“实质认同”而编码为 EX、IN 或 RE。

2. **同意并新增认知内容：按新增内容编码。**
   - 同意之后仅补充一个独立事实、直接理由、条件、反例或可能方案，且未将其与其他认知材料建立明确关系，通常按 EX 判断。
   - 同意之后连接两个及以上事实、条件、观点、评价标准或方案，并形成因果判断、比较、权衡、分类、原则或暂时性结论，按 IN 判断。
   - 编码依据是新增的认知内容，而不是“同意”本身。

3. **对具体小组答案作出决策性确认：可编码为 RE。**
   - 必须同时满足：确认对象是明确、具体、可执行或可提交的任务答案，例如具体排序、最终选择或完整方案；发言具有决定、定案、提交或结束该项讨论的作用。
   - 典型表达：“那就确定氧气排第一。”“好，最终答案按这个顺序提交。”“大家都同意的话，就定这个方案。”
   - 仅说“对”“同意”“可以”不能证明小组答案已经确定；若无法从原文确认其具有定案作用，不编码为 RE。

判断顺序：先删除“对、同意、有道理”等纯附和片段，再检查所有剩余片段。若没有任何实质内容，且原文没有明确完成具体方案的定案，则不编码；若仍有实质内容，必须编码，并考虑剩余内容是否同时体现多个不可分割的认知功能。不得因为附和语出现在句末，就把它解释为对前面认知贡献的取消或消解。

### 输出要求

- 只输出“无需调整”“拆分建议：……”或“合并建议：……”。建议说明具体边界或相邻单元，由研究员决定是否执行。
- 合并建议必须说明上述四个合并条件为何全部满足，不得只使用“语义连续”“构成完整理解单元”等笼统理由。

### 边界示例

- 保持分开：“什么叫充气展开？”与“大概是橡皮充气筏。”构成问答，分别是提出知识缺口与尝试回答，不得合并。
- 保持分开：A 说“指南针在月球上没用。”B 说“不一定，它也许能感应其他磁场。”两者围绕同一议题，但是不同说话者的主张与反驳。
- 可建议合并：A 连续说“指南针可能没用。”“因为月球没有像地球一样的磁场。”后一条只补齐同一主张的理由，两条共同表达一个认知贡献。
- 保持分开：“它应该用于在水上漂浮。”与“那就放最后。”分别是功能判断与基于判断的排序决策，认知功能不同。

## 编码类别

- `TE`（触发事件）：提出具体的问题、不确定性、矛盾或尚未解决的议题，从而启动或重新开启实质性探究。仅用于邀请发言、推进流程的程序性问题不属于 `TE`。
- `EX`（探索）：提出或交换尚未被综合的信息、意见、经验、理由、解释或可能方案。孤立判断、单一理由、物品功能说明、相关背景知识和未经确认的可能方案通常属于 `EX`。没有实质新增的重复、附和或同意不单独编码。
- `IN`（整合）：明确连接、比较或综合两个及以上认知材料，形成分类、因果关系、原则、权衡关系、结构化理解或暂时性结论。认知材料可以是事实、功能、物品性质、限制条件、观点、理由、评价标准或方案；可以来自不同说话者，也可以来自同一说话者先前或当前发言，也可以全部围绕同一个物品。`IN` 不要求综合多个人、多个物品或多个话题。判断材料数量时应按认知作用区分，不能把同一物品的功能、性质、条件和评价标准一律压缩成“一个功能认知”。单一主张及其直接、未经展开的理由通常属于 `EX`；但若发言连接物品功能或性质、任务条件与评价标准，并据此形成价值判断或相对排序结论，则属于 `IN`。不得仅因出现“因为”“所以”“但是”等连接词就判为 `IN`，也不得仅因所有内容围绕同一物品就判为 `EX`。
- `RE`（解决）：把已经形成的理解或原则应用到当前任务，提出、确认、检验或最终确定具体、可执行的解决方案。在生存排序任务中，把明确物品放入具体名次、调整具体排序、确认小组答案，或检验最终方案是否符合已同意原则，通常属于 `RE`。必须区分“提出暂定方案”和“确认最终答案”：带有“大概”“可以先”“我建议”等措辞时，只能说明正在提出或暂定方案；只有原文明示“确定”“就这样定”“最终”“提交”等定案作用时，才能描述为确认或最终答案。仅说明某物重要、提出物品可能用途，或提出尚未落实到具体任务答案的可能性，不属于 `RE`。

## 判断顺序

1. 先判断该单元的主要认知功能，并结合相邻发言和此前讨论理解其作用。
2. 提出具体疑问或矛盾，选 `TE`；程序性提问不选 `TE`。
3. 提供一个新观点、事实、理由或可能方案，但没有综合其他观点，选 `EX`。
4. 对两个及以上可识别的认知材料进行连接、比较、分类、权衡或归纳，并由此产生新的关系、价值判断或暂时性结论，选 `IN`。材料是否来自多人、是否涉及多个物品均不影响判断；同一物品的功能、性质、限制条件和任务评价标准可以构成不同认知材料。
5. 将已形成的原则或理解落实为具体排序、答案、验证或最终决定，选 `RE`。

### RE 的证据强度与上下文限制

- **暂定方案**：已经提出明确、可执行的具体答案，但保留不确定性。例如“十二、十三大概就是氧气瓶和水”“可以先把绳子放第八”。可编码为 `RE`，理由必须使用“提出”“建议”或“暂定”，不得使用“确认”“确定”或“最终”。
- **确定方案**：明确表示定案、达成小组决定或准备提交。例如“那就确定氧气第一”“最终按这个顺序提交”。可编码为 `RE`，理由可以使用“确认”或“最终确定”。
- **尚未形成具体方案**：只讨论物品功能、价值、可能用途或一般排序原则，没有落实到明确对象和具体任务动作，不属于 `RE`，应根据内容判断为 `EX` 或 `IN`。
- **相对排序与具体排序的边界**：依据功能、条件或评价标准得出“应该靠前”“不应排得很高”“价值较低”等相对排序结论，但尚未落实为具体名次或明确位置调整，通常属于 `IN`；把物品放到“第十二”“最后一位”或“某物之后”等可执行位置，才属于 `RE`。
- **指代不明**：例如“十二、十三大概就是这两个”，只有当输入上下文能够明确识别“这两个”所指的具体物品时，才可视为可执行的暂定排序并编码为 `RE`。若当前输入无法恢复指代对象，不得虚构对象或声称已经确定答案；在无法可靠判断其他认知功能时，返回空编码并说明“指代对象不明，证据不足”。

## 多重编码与理由

- 输入内容已经由研究员整理为观点单元。编码时不得直接拆分、合并或改写观点单元，也不得新增或遗漏单元；所有编码员必须基于同一套观点单元进行判断。
- 只有当单元的全部片段均为重复、附和、程序性话语或无实质认知贡献时，才返回空编码。若单元中任何位置存在实质认知贡献，即使开头、中间或结尾同时含有无编码片段，也不得返回空编码。空编码表示“已判断为不编码”，不表示“尚未编码”。
- 原则上选择最能代表该观点单元主要认知功能的一个类别。
- 当一个单元确实包含多个在语义和逻辑上不可分割的实质认知行为、拆分会扭曲原意时，可多重编码。应分别检查所有实质片段，不能只按最后一个分句或最显眼的关键词决定整个单元；不要因为一句话仅涉及多个物品或出现多个关键词就多重编码。
- 理由用一到两句中文说明，指出原文体现了什么认知功能，以及为何满足该类别的操作标准；不要评价说话者，也不要虚构上下文。

## 边界示例

- “大家觉得下一个应该讨论什么？”是程序性推进，不是 `TE`；“月球没有地球磁场，指南针还能工作吗？”提出实质性不确定性，属于 `TE`。
- “镜子可以反射阳光，可能用于远距离求救。”提供功能和理由但未综合其他观点，属于 `EX`。
- “绳子有用，因为可以绑东西。”只是一个功能主张及其直接理由，通常属于 `EX`，不能只因出现“因为”就判为 `IN`。
- “求生筏可以在水上漂浮。”只提供一个物品功能，属于 `EX`。
- “它就是普通求生筏。”只提供一个物品性质判断，属于 `EX`。
- 判断 `EX` 与 `IN` 时，先检查发言是否建立了认知材料之间的关系。只提出一个事实、用途、理由、意见或可能方案，属于 `EX`；明确比较、连接、组合、分类或权衡两个以上认知材料，并据此形成组合用途、相对重要性、条件判断或暂时性结论，属于 `IN`。不得仅因出现“可能、也许、我觉得、可能有用”等不确定措辞就判为 `EX`。
- “更重要、应靠前、风险更紧迫、不应排得很高”等是相对结论；若该结论来自对多个认知材料的比较、连接或权衡，应判断为 `IN`。只有把明确对象落实到具体名次或可执行位置时，才判断为 `RE`。
- “它用于在水上漂浮；如果没有额外科技，它只是普通求生筏，所以不应该排得很靠前。”连接功能、限制条件、物品性质与任务价值并形成相对排序结论，属于 `IN`。这些材料虽然都围绕同一个物品，仍是多个具有不同认知作用的材料，不能压缩为“单一功能认知”而判为 `EX`。
- “既然它只是普通求生筏，那就把它排第十二。”把判断落实为具体名次，属于 `RE`。
- “水是限量的，但食物没有说限量，对不对？对，我同意。”前半部分包含资源限制的比较和实质疑问，后半部分只是附和。必须忽略“对，我同意”并依据前半部分编码，不得返回空编码；后面的附和不能消解前面的认知贡献。
- “对，我同意，而且水有限、奶粉需要用水，所以奶粉应该靠后。”应忽略开头的附和，并依据后面的条件连接和暂时性结论编码为 `IN`。
- “指南针在月球上还能工作吗？如果不能，那就把它放到最后。”若两个认知行为在当前单元中不可分割，可同时编码 `TE` 和 `RE`；不能只依据最后的排序动作而遗漏前面的实质疑问。
- “水有限，而奶粉需要消耗水，所以奶粉应该靠后。”连接资源条件、物品使用条件与排序评价并形成暂时性结论，属于 `IN`；即使这些材料都由同一说话者提出，也不影响判断。
